## Majeur

### Claude Code : nouveaux événements et sémantique d'échec des hooks

- **Source** : [O] Anthropic, *Changelog* (Claude Code), v2.1.328 à v2.1.332, 19 au 25/11/2026. <https://code.claude.com/docs/en/changelog>
- **Résumé** : v2.1.332 ajoute l'événement `PreSkillShellCommand`, qui peut refuser les commandes shell en ligne d'un skill au chargement, et les skills fournis par des serveurs MCP (bêta, nommés `serveur:skill`). v2.1.331 restreint `retry: true` de `PermissionDenied` aux appels demandés. v2.1.329 cesse, en Code Mode, de refuser l'appel d'outil quand un `PreToolUse` est en erreur ; v2.1.328 étend `onFailure: "block"` aux hooks `mcp_tool` et ne lance plus `UserPromptSubmit` sur la sortie des scripts en Code Mode.
- **Impact** : [chapitre 07](../../knowledge/07-hooks-et-garde-fous.md), tableau des événements et « Limites à connaître », modifiés dans cette PR. Les skills issus de serveurs MCP concernent l'état du débat du [chapitre 05](../../knowledge/05-skills.md), non modifié (plafond de trois chapitres) : à reprendre lors d'une prochaine exécution.

### L'équipe Claude Code formalise ses règles de vérification

- **Source** : [O] Osmani (équipe Claude Code), *How the Claude Code team thinks about verification*, 16/11/2026. <https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/>
- **Résumé** : les tests de bout en bout sont jugés les plus difficiles à tromper ; « If a change can modify the check that judges it, the check is broken » ; les règles de revue sont lues sur la branche de base ; un contrôle qui échoue encore après trois tours fait intervenir un humain ; les tests instables ne peuvent être ni ignorés ni relancés jusqu'au vert ; une nouvelle barrière démarre en mode observation.
- **Impact** : [chapitre 09](../../knowledge/09-verification-et-evaluation.md), sections « La qualité des tests » et « Organiser la revue automatique », modifiées dans cette PR. Cohérent avec le contrôle de périmètre de la veille, exécuté depuis la branche de base.

### Bacs à sable externes pour agents de code

- **Source** : [P] Willison, *External sandboxes for coding agents*, 17/11/2026 (billet de lien vers Prime Radiant, avec qui l'auteur a travaillé ; article source non lu). <https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/>
- **Résumé** : le code exécuté par l'agent tourne dans un bac à sable dédié, l'agent restant à l'extérieur ; trois implémentations (v86, Apple Containers, Quicksand) exposent la même API locale ; proxy HTTP en liste blanche et substitution des identifiants pour que l'agent ne détienne pas les secrets.
- **Impact** : [chapitre 10](../../knowledge/10-securite.md), section « Les couches de Claude Code », modifiée dans cette PR (marqué **Émergent**), avec deux points du changelog : dialogue de confiance indiquant où sont déclarés les hooks (v2.1.329) et `claude mcp add-json <nom> -` (v2.1.327).
